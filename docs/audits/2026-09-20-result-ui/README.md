# 第五轮：结构化结果页与主屏触摸

基线 `06d35e1`，分支 `stage6/integration`。温升测试按用户要求继续延后；仅使用独立调试包，PR #9 不合并。

## 先复现再修复

使用 diagnosing-bugs 流程，在实际生产 View 的主机测试中捕获绘制命令和触摸状态：[修复前日志](before.log)有三组失败。

- 比例结果页绘制了内部 `101,202,303` 输入串及编辑光标。
- 点击结果页顶部会退出结果态，编辑不可见的内部输入。
- 主屏统计卡片点击不打开应用。

根因分别是：只有 TABLE 布局禁止绘制表达式；结果触摸沿用普通表达式编辑手势；主屏卡片仅绘制，没有独立触摸入口。截图来自上一轮二次回归结果，也支持第一项，不以主机替身代替实际像素检查。

## 修复边界

1. **显示**：所有结构化应用结果不再绘制序列化输入、自然表达式光标或选区手柄。KEY_VALUE/MATRIX/VECTOR 结果使用原输入区腾出的空间；TABLE 的行数和分页布局不变。TEXT 类型走普通结果文字绘制，避免空白结果。
2. **触摸**：结构化结果显示区点击/水平拖动不再移动隐藏光标；长按任意结果区域打开剪贴板菜单。不改变物理键及返回表单原有语义。
3. **复制**：结构化结果菜单不暴露“复制计算过程/选区”，因为此处内部串不是用户计算过程；保留复制结果、Ans 和粘贴。普通计算的独立过程/结果复制和选区操作不变。
4. **主屏**：绘制和命中共用卡片边界；当前可见页映射到核心 `activateHomeItem(index)`。同一手指在卡片内松开才进入应用；滑动超阈值后即使滑回也取消，系统取消/失焦/离开卡片均不触发。空白区域不激活。保留方向键和 Page 翻页。
5. **状态边界**：直接打开应用仍由核心负责，View 负责触摸命中、旧任务失效和反馈；不通过伪造重复方向键来选择卡片。

没有改数学引擎、签名、正式包名或键盘字号，没有加入持续刷新、轮询或后台服务。
