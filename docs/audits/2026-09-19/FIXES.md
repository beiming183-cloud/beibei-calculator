## 防持续高负载措施

1. **计算可取消**：数值函数取值前后检查中断，多项式循环检查取消；AC、新输入和失焦使旧任务失效。取消异常原样传给任务层，不当作语法错误发布。
2. **预算不被嵌套绕过**：核心一次 evaluate 打开共享预算，多个并列求和、嵌套积分等不各自重新计时。默认上限是 100 万次数值函数取值、2 秒；过大求和可在第一次函数调用前拒绝，超限使用已有 TIMEOUT 错误。
3. **不以精度换省电**：没有降低求导/积分的正常误差容限；预算超限明确报错。积分权重改为复用常量，中心点不再重复求值。
4. **后台不继续输入**：松手、失焦、销毁清理 Handler 重复/长按回调；销毁停止执行器，重新挂载可重新计算。
5. **不引入空闲刷新循环**：界面沿用事件触发刷新，没有为“计算中”新增持续动画或轮询。

2 秒是协作式检查点预算，不是强制中止任意代码的操作系统 watchdog；一次未到检查点的代码片段不能被强杀。100 万次是数值函数取值次数，不是所有 Java 指令数。这些是防持续高负载的保护机制，不能代替耗电和温度测量。
