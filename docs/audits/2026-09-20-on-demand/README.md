## 复现与修复

按 diagnosing-bugs 流程，先在实际生产 View 的主机测试中复现两项失败，见 [修复前日志](before.log)：

- 相同输入正在等待计算时，连续 50 次 EXE 不断取消旧请求、复制计算状态、重新提交。
- 后台已计算完成、UI 回调尚未执行时，再按 EXE 也会丢掉待显示结果重新计算。

核查顺序：重复提交入口、UI 回调等待阶段、是否多个计算线程。根因是 `dispatchKey` 在识别重复请求前无条件使原任务失效；计算器本来使用单线程执行器，并非每个应用同时计算。

修复只记录当前执行键：同一输入版本、同一执行键、仍处于计算/回调等待阶段时复用原请求。编辑、粘贴、切换功能、失焦等原有失效入口保持不变；修改输入后必须创建新任务。结果已经正式显示后的再次执行行为不变，不缓存数学结果，不合并可能语义不同的执行键。

## 按需执行边界

- `CnCwModeEngine.evaluate` 按当前应用 switch 分派，不逐个运行未选应用。
- 单个 View 使用一个计算工作线程；线程按提交任务启动，空闲等待不是持续计算。未增加线程池、轮询、预计算、后台服务。
- 重复执行合并不依赖计时器，只有常数时间状态比较。
- 切换功能使旧任务取消且旧回调失效。取消依赖计算代码配合中断，不能由此声称所有数值路径都瞬间停止。
- 现有延迟任务用于长按/连续输入，原有松手、失焦、销毁取消检查继续通过。
